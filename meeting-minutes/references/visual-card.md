# 会议对齐卡片

仅在任务要求视觉产物时阅读。卡片应让读者独立对齐会议内容：图形承载关系和差异，短文字保留具体信息。

## 内容先于排版

从已核对的纪要建立本图内容清单，选择适合本次会议的组织方式，不套固定分区模板。与会议有关时，应覆盖：

- 阶段方向、已决定的事及选择依据；候选方案的主要取舍。
- 技术或执行进展：当前已做到什么、成立条件、缺口、下一步如何验证。
- 到人的行动：姓名、具体任务、产物或验证目标、依赖及已有时间要求；标明已认领、请求认领或建议分工。
- 需要下次对齐的问题；远期设想与近期任务各自的状态。

纪要没有提供的信息保持未知；不为填满版面补造内容。重要限定语随对应结论放置，例如“数据集结果”“尚未实测”“负责人待定”。未来任务用待办状态，不用完成勾选；不把讨论顺序画成已确认的实施顺序。

## 选择能携带信息的图形

| 内容关系 | 可用表达 | 要保留的事实 |
| --- | --- | --- |
| 执行或技术路径 | 分支流程、输入至结果的链条 | 已验证段、缺口、下一步与依赖 |
| 候选方案取舍 | 共用尺度的对照、简洁矩阵 | 相同评估维度、收益、代价与未知 |
| 当前结果和目标 | 前后对照、阶段进度 | 当前边界、下一步验证；无依据不画百分比 |
| 按人推进 | 姓名对应行动的紧凑行、泳道 | 任务、认领状态、时间与阻塞条件 |
| 时间关系 | 时间带、里程碑 | 已有日期或相对期限；讨论窗口不画成交付日 |
| 关键数量 | 单一图形配数字、有限重复单元 | 精确数量与单位；示意图注明示意 |

优先用一个图形解释一组关系，减少装饰性图标。箭头、颜色、空间位置须有一致含义；建议路线与已确定路线有明确区分。图示推导不应增加会议没有讨论过的因果关系。

## 风格与信息密度

先查看用户参考图，抽取字重与字号层级、配色、留白、对齐、图标和分隔方式。仅继承视觉语言，内容以本次纪要为准；用户要求加密内容时可以重排布局。

用户未指定其他风格时，以 Linear / Notion 式清晰排版为默认：浅底、深色文字、有限强调色、稳定网格、清楚的层级。主要靠间距与对齐分组，边框和分隔线只用于确有必要的关系。无需复制品牌标志或产品界面。

信息不足时，补上缺失的具体任务、验证条件、方案差异与未决问题，不能只放大标题或增添图标。信息拥挤时，先压缩标题区、装饰、重复词和过大留白，再重排图形；保留足够正文尺寸，不靠堆小字塞入全文。按内容选择画幅，兼顾整体阅读与局部放大；用户指定单张时把关键对齐信息留在一张内。

## 生成与检查

1. 查看当前环境可用的 GPT 图像工具及图像生成指导（如可用的 `imagegen` skill）。使用用户指定且实际可用的工具；优先当前已可用的 GPT 图像生成能力。接口未暴露或未返回的模型版本，不能仅因用户提到某个版本便宣称使用了它。
2. 提示词写清本次会议内容清单、精确姓名与关键文字、状态语义、图形关系、阅读顺序、视觉风格和参考图用途。编辑现有卡片时，明确目标图片、需要增加或修正的内容及保留部分。
3. 生成后实际查看完整图片并检查必要局部。核对中文是否完整可读，人名、数字、日期、期限是否准确，关键内容是否遗漏，箭头与阶段顺序是否正确，图示数量是否与数字相符，待办是否被误画成已完成。
4. 发现错误时使用图像工具做针对性修正，保留已正确的区域。重复图标数量持续失准时，改为一个图标加准确数字等稳健表达；不接受“旁边数字正确”但图形表达矛盾的结果。
5. 再检查最终图片，而不是只确认工具成功返回。若关键事实或文字仍不可靠，明确剩余问题并提供正确的文字纪要，不能把未核验图片报告成完整交付。

记录最终采用的提示词、工具返回的实际模型信息（若可知）及参考图来源，随图片保存到项目规定的持久目录。最终展示核验后的图片并提供下载路径。
